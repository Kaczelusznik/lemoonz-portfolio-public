# LeMoonz

LeMoonz is a portfolio and commissions website I am building for an independent artist and animator.

It started as a fairly simple web project, but it has slowly turned into one of the main projects I use to learn how real web applications grow, change and eventually need to be rebuilt.

The production source code is private because the project contains client-specific content, artwork and assets. This repository is a public overview of the project and its development.

## Where the project is now

The current working version is built with:

- HTML
- CSS
- JavaScript
- Node.js
- Express
- EJS
- Railway

This version is already deployed and works as the current prototype / production base.

Most of my work so far has focused on responsive layouts, visual structure, EJS views, routing, deployment and translating the artist's ideas into an actual website.

## What I am changing

The current stack works, but I reached a point where I want to take the project further and use it to learn a more modern full-stack workflow.

The next stage is focused on:

- React
- TypeScript
- Python
- PostgreSQL

I am not planning to throw everything away and rewrite the whole project just so I can put React in the README.

The idea is to move gradually.

I want to rebuild parts of the website, compare the old and new approaches and understand what the new stack actually improves.

React and TypeScript are the main focus on the frontend. Python is the direction I want to explore for the backend, with PostgreSQL planned for data that should eventually stop living directly in templates or source files.

## Why LeMoonz?

I could make another todo app to learn React.

I would rather learn it by rebuilding something real.

LeMoonz already has:

- a real client
- real requirements
- an existing design
- content that changes
- responsive problems to solve
- a deployed version that I can compare against

That makes it a much better learning project for me than starting another isolated tutorial.

## The goal

The finished project should be a responsive portfolio and commissions platform that is easy for visitors to use and easier for me to maintain and extend.

I want the final version to have a cleaner frontend architecture, reusable components, a proper API where it makes sense and a better separation between presentation, application logic and data.

But the goal is not to use as many technologies as possible.

The goal is to build something the client is happy with and a codebase that I actually understand.
